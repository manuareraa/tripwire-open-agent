Decisions that know when to reopen themselves.

Tripwire is a team of AI agents that decides whether to keep, dual-source or exit a supplier. It writes down exactly which data each decision relied on, and sets tripwires: the conditions that should make us look again. When the data changes, only the decisions whose tripwire fires are reopened.

The idea in one minute

Most decisions go stale quietly.

A buyer decides to keep a supplier based on this quarter's numbers. Next quarter the numbers move, and nobody knows which past decisions were built on them.

1

The problem

Re-checking every decision whenever any data changes is slow and expensive. Not re-checking means acting on stale reasoning.

2

What Tripwire does

Every decision is saved with the exact rows and query results it used, plus a few tripwires. A data change re-checks only the decisions that depend on that row.

3

What you get

Decisions you can audit down to the SQL query, a human sign-off on risky calls, and work saved on every change that doesn't matter.

How it works

Four steps, every one traced.

Every step the agents take is written to a trace you can read in the console, so you can see why a decision came out the way it did.

1

Decide

The agents plan which approved SQL queries to run, analyse the results and draft a decision. An Evidence Critic checks every number and sends weak work back.

keep · dual_source · exit
2

Record lineage

Each claim is stored in memory with the row it came from and a fingerprint (hash) of the query result. Recalled claims whose data has changed are thrown out.

supplier_spend:SUP-06 · b8099b…
3

Set tripwires

The Decider proposes 2–4 conditions that would change its mind. Code checks they are valid; a model never judges its own tripwire.

spend_share > 0.45
4

Watch and reopen

When a row changes, the Watcher finds the decisions built on it, evaluates their tripwires in code, and reopens only those that fire.

1 reopened · 19 work saved
A person stays in charge. Decisions are only proposals. Risky ones are escalated and need a written reason to approve. Only an approval writes back to the data layer.

The agent team

Six agents and a watcher, each with one job.

The agents hand work to each other and can push back. The Evidence Critic can send work back up to three times before a decision is final.

Guide

What's real, and what the words mean.

Honest about the data

  • RealQuarterly financials for 20 US-listed companies, from SEC EDGAR filings (public domain).
  • SyntheticThe buyer, its spend with each supplier, and two of the three demo changes. Picking a company says nothing about it as a real supplier.
  • NamedWhen a model or service is unavailable, the fallback is named in the trace and the rationale ("Rule-based policy: …"). It is never shown as a model answer.
  • Labelled"Liabilities to equity" is total liabilities ÷ equity, not interest-bearing debt only.

Using the console

  • Step 1Pick a supplier and press Decide. The agents run and the decision appears in the middle.
  • Step 2Read why, check the evidence, then Approve or Reject. Escalated decisions need a reason.
  • Step 3Apply a data change. The Watcher reports what it checked, what it reopened and what it left alone.
  • AnytimeThe agent trace on the right shows every handoff, query, critique and fallback. Press Tour to replay the walkthrough.

Glossary

Decision
Keep the supplier, dual-source (add a second supplier for the same parts), or exit (move the spend elsewhere).
Tripwire
A condition attached to a decision, like "spend share above 45%". If the data crosses it, the decision is reopened.
Lineage
The exact table rows a decision read. It lets the Watcher find which decisions a change affects.
Result hash
A fingerprint of a query's result. If the data changes, the fingerprint changes, so stale evidence is easy to spot.
Confidence
How sure the Decider is, from 0 to 100%. It is lowered when evidence is missing or was rejected.
Escalated
Flagged by the Risk Officer as high-stakes. A person must give a written reason to approve it.
Superseded
Replaced by a newer decision on the same supplier, usually after a reopen. The old one is kept for audit.
Work saved
Decisions that depended on the changed row but whose tripwires didn't fire, so they weren't re-run.
